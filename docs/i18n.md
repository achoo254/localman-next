# Đa ngôn ngữ (i18n) của web

Giao diện có ba ngôn ngữ: English (`en`, mặc định), 中文 giản thể (`zh-CN`) và Tiếng Việt (`vi`). Danh sách và mặc định nằm ở `packages/shared/src/locales.ts` (`SUPPORTED_LOCALES`, `DEFAULT_LOCALE`, `isLocale`, cũng có trong `@localman/shared/constants`). i18n tự viết, không thêm thư viện, để landing giữ nhẹ.

## Chọn ngôn ngữ

- Thứ tự: `?lang=<locale>` (được ghi nhớ, để qua vòng đăng nhập IdP vẫn giữ) > lựa chọn đã lưu trong `localStorage` (`localman-locale`, đọc/ghi trong try/catch) > `en`. Không đoán theo ngôn ngữ trình duyệt: sản phẩm mặc định tiếng Anh.
- `LanguageSwitcher` (`src/i18n/language-switcher.tsx`) là menu radio (English / 中文 / Tiếng Việt, mỗi mục có `lang` riêng) ở header công khai, header app (từ 640px) và footer. Người đã đăng nhập đổi ngôn ngữ thì app gọi `PUT /api/v1/users/me/locale` với `{ locale }` để thông báo trong app, Web Push và Telegram dùng đúng ngôn ngữ; lỗi báo bằng toast (404 của bản API cũ chưa có operation thì bỏ qua).
- Đồng bộ với tài khoản (`src/i18n/account-locale-sync.ts`, chạy trong `I18nProvider` khi phiên đã biết, không tự gọi `/users/me`): trình duyệt chưa có lựa chọn (không `localStorage`, không `?lang=`) mà `locale` của tài khoản khác `en` thì áp ngôn ngữ của tài khoản và lưu lại; trình duyệt đã có lựa chọn khác tài khoản thì giữ lựa chọn của trình duyệt và `PUT` lên tài khoản.
- `<html lang>` đổi theo ngôn ngữ đang hiển thị.

## Tải và prerender

- `en` nằm trong bundle chính; `vi` và `zh-CN` là chunk riêng, `import()` khi được chọn (`src/i18n/load-messages.ts`, lỗi tải thì lần sau thử lại).
- Landing prerender bằng `en` (`index.html` có `lang="en"`, title/description tiếng Anh). Trình duyệt hydrate bằng `en` để markup khớp, rồi `I18nProvider` chuyển sang ngôn ngữ của khách khi dictionary tải xong. Mọi path khác: `main.tsx` tải ngôn ngữ trước rồi mới render, nên trang vẽ một lần, đúng ngôn ngữ.

## Dùng trong component

```tsx
import { useI18n, useT } from "../../i18n/i18n-context";
import { renderRich } from "../../i18n/rich-text";

const t = useT();
t("layout.skipLink");
t("layout.accountMenu.trigger", { name });           // {name}
t("landing.relations.endpointCount", { count: 25 }); // số nhiều
renderRich(t("landing.relations.lead"));             // <code>, <b> trong câu
const { locale, formatNumber, formatDate } = useI18n();
```

- `t()` kiểm kiểu từ dictionary `en`: key sai, thiếu tham số, thừa tham số, hay `count` không phải số đều là lỗi typecheck.
- Tham số kiểu số được định dạng theo ngôn ngữ (`10,000`, `10.000`); muốn giữ nguyên (năm) thì truyền chuỗi.
- Số nhiều: lá là object theo category của `Intl.PluralRules` (`{ one, other }` cho en; `vi` và `zh-CN` chỉ cần `{ other }`), `{count}` là số truyền vào. Vì vậy namespace không được có key tên `other`.
- Câu có đoạn code hay chữ đậm giữ nguyên câu trong dictionary với thẻ `<code>…</code>`, `<b>…</b>` (không lồng nhau) rồi render bằng `renderRich(text, renderers?)`; truyền renderer khi cần class riêng hay link (trang docs dùng `docsRich` với `<link>`, `<em>`, `<angle>secret</angle>` cho `<secret>`). Nội dung trong thẻ không được chứa `<`; đoạn code có `{` hay `<` truyền qua tham số (`<code>{errorBody}</code>`). Code mẫu (lệnh, JSON, ví dụ fetch/axios/curl) không dịch.
- `formatNumber` / `formatDate` theo ngôn ngữ hiện tại, ngày theo múi Asia/Saigon (vi giữ `dd/mm/yyyy`). `src/lib/format.ts` cùng định dạng đó cho code không có `useI18n()`.
- Hàm thường chạy ngoài React (`errorMessage`, `invalidJsonMessage`, `lib/format.ts`) đọc ngôn ngữ đang hiển thị qua `activeTranslator()` (`src/i18n/active-translator.ts`, `I18nProvider` cập nhật khi đổi ngôn ngữ, không có provider thì là tiếng Anh). Chỉ dùng cho hàm ngoài React; trong component luôn dùng `useT()` / `useI18n()` để component vẽ lại khi đổi ngôn ngữ. Module chỉ đặt tên lỗi hay nhãn (validation, mã lỗi) thì trả key, component dịch khi render.
- Component render ngoài `I18nProvider` (test một component) nhận tiếng Anh.

## Thêm key

1. Thêm vào `src/i18n/messages/en/<namespace>.ts`. Mỗi khu vực app một namespace (`common`, `auth`, `layout`, `landing`…); namespace mới thì khai trong `en/dictionary.ts`, `vi/dictionary.ts`, `zh-CN/dictionary.ts`.
2. Đặt tên: `namespace.khối.phần` camelCase theo nơi hiển thị, ví dụ `landing.hero.howItWorks`, `layout.accountMenu.signOut`. Chuỗi dùng ở nhiều khu vực (CTA, "Thử lại", "Đặt lại") để trong `common`.
3. Thêm bản dịch ở `vi/<namespace>.ts` và `zh-CN/<namespace>.ts` (kiểu `Messages["<namespace>"]`): thiếu hay thừa key là lỗi typecheck; `dictionaries.test.ts` kiểm thêm placeholder, thẻ và dạng số nhiều khớp với `en`.
4. Văn phong theo `docs/ux-writing.md` (mục riêng cho từng ngôn ngữ); thuật ngữ kỹ thuật (mock, resource, endpoint, project, schema, field, MCP, Faker…) giữ tiếng Anh ở mọi ngôn ngữ.

Tên ngôn ngữ (endonym) không dịch, nằm ở `src/i18n/locale-names.ts`.

## Kiểm tra

`pnpm check:i18n` (chạy trong `pnpm lint` và CI; logic ở `scripts/check-i18n/`):

- Không có chữ tiếng Việt trong string literal, template hay JSX text của `apps/web/src` ngoài `src/i18n/messages/vi/**` và file test (comment không tính). File chưa chuyển nằm trong `scripts/check-i18n/pending-files.ts`; script in số còn lại và báo lỗi khi một file trong danh sách đã sạch. Danh sách phải về rỗng.
- Không có tên đối thủ (`mockapi`, `postman`, không phân biệt hoa thường) trong `apps/web/src` (ngoài test và comment) và `apps/web/index.html` (ngoài comment).
- Bỏ qua một dòng bằng comment `check-i18n-ignore: <lý do>`, bắt buộc ghi lý do.

## Server

API giữ ngôn ngữ trên user để thông báo nói đúng ngôn ngữ của người nhận (chi tiết luồng ở [system-architecture.md](system-architecture.md#thông-báo)).

- `locale` của user: một trong `SUPPORTED_LOCALES`, chưa chọn thì `en`. Đặt bằng `PUT /api/v1/users/me/locale` với `{ locale }` (`users.setLocale`, có MCP tool `set_locale` trong toolset `users`); giá trị khác danh sách trả 400 `VALIDATION_ERROR`. `GET /users/me` trả `locale`. Đăng nhập lại không ghi đè `locale`.
- Thông báo trong app lưu `type` + `params`, render lúc đọc theo `locale` hiện tại, nên `GET /notifications` luôn trả `title`/`body` đã dịch, kể cả thông báo nhận trước khi đổi ngôn ngữ. Bản ghi cũ dạng chữ (tiếng Việt) trả nguyên.
- Web Push và Telegram render theo `locale` của người nhận lúc gửi. Tin báo owner theo `locale` của owner (user có chat trùng `OWNER_TELEGRAM_CHAT_ID`, rồi owner đầu tiên trong `OWNER_SUBS` đã chọn), còn lại `en`.

Chuỗi ở `apps/api/src/i18n/`:

- `messages/en.ts` là nguồn; `ServerMessages = typeof en`. `messages/vi.ts` và `messages/zh-cn.ts` khai kiểu `ServerMessages`, nên thiếu hay thừa key, hay hàm sai tham số, là lỗi typecheck. `server-messages.ts` có `messagesFor(locale)` và `formatCount(locale, n)`.
- Câu có tham số là hàm (`body: (p) => ...`), không có cú pháp placeholder; số và tháng được định dạng trước khi truyền vào (`formatCount`, `formatMonth` riêng từng ngôn ngữ: `October 2026`, `2026年10月`, `10/2026`).
- `vi` giữ đúng câu tiếng Việt trước khi có i18n; thuật ngữ kỹ thuật (mock, project, URL, API, Pro) giữ tiếng Anh ở mọi ngôn ngữ.
- Thêm loại thông báo: thêm type và schema tham số vào `NOTIFICATION_PARAMS` (`modules/notifications/notification-events.ts`), chữ và nhãn vào cả ba từ điển, rồi template trong `notification-texts.ts`. Module gửi chỉ truyền `{ type, params, link }`.
